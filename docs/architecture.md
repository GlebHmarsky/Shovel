## History context execution and default network targets (0.29.0)

`ShellHistoryActions` creates localized command descriptors from the clicked CommitRow, tab and page identity. `MainWindow.HistoryMenu` selects the clicked row and defers selection-driven committed-file reads until the menu closes; it does not inspect repositories. Commands reject replaced pages/tabs and share the shell action gate. Reset confirmation uses frozen branch/tip/target and mode-specific consequences. After submission, `PrepareBranchManagementAsync` validates the local snapshot without remote enumeration; `HistoryActions.cs` builds explicit commands inside the existing common-directory mutation mutex. Config/identity/HEAD/ref freshness checks run again before writing. Independent Git clients can still race between observation and command execution; Git's own locks/protections remain authoritative.

Full SHA-1/SHA-256 targets are validated as commit objects off-thread. Checkout uses `switch --detach` without force/ignored-file overwrite; Reset uses the selected mode, blocks another worktree holding the same branch and disables recursive submodule updates. Revert uses `--no-edit`, validates mainline against original commit metadata (not projected stash graph parents) and inspects operation/unmerged state even on nonzero exit. Existing process limits, hooks/signing, cancellation, output and reconciliation apply; cancelled work is reinspected, never rolled back automatically. Missing partial-clone objects fail locally. Sparse/linked/LFS/filter/signing edge cases beyond the focused fixtures still need representative validation. The selected and previous hashes remain in in-memory operation output, not diagnostic logs.

`DefaultNetwork.cs` resolves targets only after direct-button submission; option dialogs remain cached. Fetch consults branch.remote then origin/sole remote. Push asks `for-each-ref` for push remote and upstream metadata, then resolves single-branch push.default locally. Installed Git 2.51.1 returns an empty push:remoteref for ordinary default refspecs, so that field is not treated as a complete resolver. Current maps to same-name; upstream requires the same remote; simple requires same-name upstream when returning to that remote, or same-name destination for a separate configured push remote. Custom remote.push refspecs, matching/nothing, missing targets and automatic setup fall back to a localized options/setup error. No implicit multi-ref/force/tag push or config change. The action VM's preparation callback passes resolved options through the normal authenticated execution path; shared validation catches subsequent config/ref changes.

Official semantics checked 2026-10-29: [detached switch and protections](https://git-scm.com/docs/git-switch), [reset modes and recovery limits](https://git-scm.com/docs/git-reset), [revert mainline and sequencer](https://git-scm.com/docs/git-revert), [ref atoms](https://git-scm.com/docs/git-for-each-ref) and [push/remote configuration](https://git-scm.com/docs/git-config#Documentation/git-config.txt-pushdefault). [Product](product.md#history-actions-and-network-split-buttons-0290) owns user-visible behavior; [roadmap](roadmap.md#current-status) owns evidence.

## Direct default Pull (0.28.0)

`ShellActions.DefaultPullCommand` uses a cached attached-branch upstream to select one remote and branch, then enters the same `OpenActionAsync` lifetime as dialog submission. It starts `GitActionViewModel.RunCommand` without showing options. `PullCommand` still opens the existing dialog and is bound to the adjacent arrow. Main-button defaults remain Rebase/auto-stash off; modal choices are per attempt, with no settings migration. Both routes preserve the existing timer, output, authentication, cancellation, common-repository exclusion and reconciliation. No opening-time filesystem/process work or extra confirmation is introduced.

Before direct execution, `DefaultPull.cs` checks the prepared current branch's actual upstream remote and server ref using one bounded, off-thread `for-each-ref` call. A missing/ambiguous cached remote disables only the main action; a changed/custom server mapping fails before fetch with a localized route to Refresh/options. Do not substitute the first configured remote. Existing identity/ref/config checks and Git's dirty-worktree protections remain in the shared pipeline. This saves interaction steps, not Git subprocess execution time. Local `.` upstreams and ambiguous/nonstandard tracking layouts use explicit modal targets rather than a guessed direct Pull.

Official format fields checked 2026-10-29: [Git for-each-ref upstream remotename/remoteref](https://git-scm.com/docs/git-for-each-ref). Source labels in the future conflict editor and detached-history Checkout are confirmed product decisions, not implemented by this increment.

## Workspace cleanup and remote setup (0.27.0)

Sidebar horizontal scrolling is disabled; stretched grid headers trim names while preserving trailing counts/selectors and accessible labels. Width storage no longer clamps to 320 DIP. Restore/window resize fits it to available width minus a 180-DIP workspace and splitter; no new settings schema. Page controls/range/status live under View, read limits in Diagnostics. Wheel input past a page edge invokes existing cancellable paging commands; Ctrl+Page Up/Down and menus cover keyboard access. Pages, caches and limits are unchanged, not unbounded appended rows. Failed reads over retained rows expose a diagnostic link. Main footer is removed; settings/tool feedback remains visible in the center caption and details.

`RemoteSetupViewModel`/window opens solely from cached remote names. Submit closes it and uses the standard action/progress/result pipeline. `RemoteSetup` validates repository identity, common-directory mutation gate, configuration stamp and name, then runs literal `git remote add -- <name> <location>` without `-f`. Git owns config locking and duplicate rejection; no global writes, remote probes or automatic fetch. HTTP(S) embedded passwords/query tokens are rejected; credentials belong to established Git helpers. A failure/cancellation still reconciles local state; no rollback promise. Set/Unset upstream reuses tested branch management and existing fetched refs, now under Repository. Remote edit/delete remains deferred. [Official git-remote documentation](https://git-scm.com/docs/git-remote), checked 2026-10-29, confirms that `add` saves configuration and only `-f` starts a fetch.

## Caption and history layout (0.26.0)

MainWindow uses built-in [WPF WindowChrome](https://learn.microsoft.com/en-us/dotnet/api/system.windows.shell.windowchrome?view=windowsdesktop-10.0) (official API checked 2026-10-29): 32-DIP caption, 6-DIP resize zone and interactive menu/caption-button regions. Caption buttons call SystemCommands and existing Closing handling; no transparent window, drag polling or new dependency. Native maximize work-area/hit-testing is delegated to WindowChrome. No claim of Windows 11 native snap-hover flyout parity; desktop drag/resize/maximize, DPI, system-menu and accessibility behavior remains unverified.

CommitGraph retains fixed slots, including vacancies and multiple tracks waiting for the same ancestor, in GraphCursor. First-parent tracks stay in place; side tracks converge only on the shared target's row. Trailing empty slots are trimmed, internal slots reused without displacing active tracks; the existing 64-column guard applies. CommitGraphCell uses up to 10-DIP quadratic turns and straight inter-row segments. Core remains WPF-independent. Original commit parents are never altered in stored details.

StashHistory reads bounded parent metadata for saved stash tips, then determines which index/untracked parents are private using [rev-list ancestry exclusion](https://git-scm.com/docs/git-rev-list) (checked 2026-10-29). Normal refs/HEAD and stash bases protect independently reachable objects. No-stash repositories pay no additional process cost. Usually two extra local processes run per history session; SHA-256-safe batches of 64 candidates handle up to 512 internals/256 tips. Reads keep existing process deadlines, cancellation and 4-MiB output limits; unusual ancestry exceeding the bounded result reports a limit. Reachability can traverse older/divergent history and is not guaranteed constant-time. These reads stay off-thread, but representative large-repository latency is still unmeasured.

HistorySession retains the hidden-ID set. HistoryCursor separates visible Offset from RawOffset so log over-read (200 + one lookahead + bounded hidden count) fills a visible page without skipping or duplicating normal commits. ExpectedFirst/fingerprint validation still rejects changed snapshots. Ref locating filters the same IDs and maps back to the raw offset. Only graph input projects each conventional two/three-parent stash to its first parent, even when an internal object must remain visible independently. GraphRow marks stash nodes for a hollow-square glyph; real abandoned base ancestry stays connected. CommitRecord and inspector contents retain the real parents. No worktree/index/stash mutation or implicit network request is added.

## Operation presentation (0.25.0)

`OperationActivity` is an immutable App-layer snapshot (attempt identity, title, phase, elapsed seconds, typed outcome). `GitActionViewModel` and `CommitViewModel` reuse their existing stopwatches and publish terminal snapshots only after reconciliation. Commit-and-Push reports the push outcome separately from the already retained commit result; failed refresh cannot appear green. `ShellOperationActivity` forwards the selected command's snapshots, retains its last result and clears transient feedback on tab selection. Since 0.27.0, selected history/refresh/paging/ref-locate reads publish their existing stopwatch with generation-bound attempt identity. Read cancellation/failure has its own terminal outcome; action reconciliation suppresses the subordinate read capsule. Secondary status/diff reads remain quiet. No new Core/process work, polling or dependencies.

`OperationIndicator` owns only layout and a WPF opacity animation: fixed 88-DIP capsule column, tabular digits, 180-ms entrance, three-second completion hold/two-second fade. Same-attempt ticks/terminal notifications cannot restart it; a new attempt/tab clear replaces the old animation and unload releases it. Windows disabled client-area animations/high contrast use a delayed hide instead. The non-ticking caption announces phase/outcome; full timing help is localized. Errors/details remain persistent after the visual fades. This is presentation timing, not a throughput optimization or desktop performance measurement. [Theme rules](theme.md), [UX](product.md#operation-feedback-0250).

The animation uses WPF's existing clock APIs ([official clock animation guidance](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/graphics-multimedia/property-animation-techniques-overview), checked 2026-10-29). Focused headless checks seek that clock explicitly; an offscreen tree has no normal desktop render loop and cannot establish real-time fade smoothness.

The history row style binds the existing author-identity relationship to `Theme.AuthorPeer` background only; selected/high-contrast rows retain their normal styles. `CommitGraphCell` draws straight segments/rounded joins at 16-DIP lane spacing with palette-appropriate colors. This is rendering only: Core lane assignment, ordering, cursors and read limits are unchanged. A one-row UniformGrid distributes repository tabs; history/file virtualization remains unchanged.

`ShellWorkspaceTools` owns explicit commands/status and profile preferences; `RepositoryTools` owns worker-thread discovery and structured process start. No discovery at startup or menu opening. Known Git roots/App Paths/standalone and bounded Toolbox directories supply candidates; a file picker handles custom/missing installs. Rider inspects only root-level project filenames, never project content or recursive trees. No PATH/shell command interpolation. `ProcessStartInfo.ArgumentList` passes paths unchanged; a process handle is disposed after dispatch, without waiting for or owning the editor/terminal. The existing external-program lifetime limitation remains: shared editor/browser work is not tracked through project closure, so future updater coordination must address it. No actual desktop handoff was run during development checks.

Rider accepts a project/folder argument and supports `.uproject` without generated solutions: [command line](https://www.jetbrains.com/help/rider/Opening_Files_from_Command_Line.html), [Unreal projects](https://www.jetbrains.com/help/rider/Unreal_Engine__Before_You_Start.html). Sources checked 2026-10-29. Tool availability/version behavior outside detected installs is not assumed; failures remain visible without installation/configuration changes.

`AppTheme` applies shared Dark/Light semantic resources and notifies native title-bar subscribers; high contrast overrides both palettes. Schema **5** adds appearance and optional executable paths; schemas 1–4 migrate with dark default, using existing atomic save/backup behavior. Choices save asynchronously and are captured again on shutdown; save failure leaves the session usable and reports unsaved preferences. These settings contain paths, not credentials or project content. Older binaries treat schema 5 as read-only; the pre-migration `.bak` is the manual recovery source, not automatic downgrade. No new dependency or theme-driven Git/network work.

## Repository sidebar (0.23.0)

`ShellSidebar` builds immutable nodes/commands from each tab's history refs, stash cache and `RepositorySidebar` metadata; `RepositorySidebarView` owns selection/keyboard/context-menu routing only. Single-click navigates, branch activation switches, and submodule selection opens a child tab. Branch management and stash commands reuse their existing implementations. Menus perform no preparation. Secondary reads start after first history, serialize/cancel across tabs, check tab/snapshot before binding, and use the existing three-tab cache eviction/30-second activation freshness. No polling. Expansion/selected tree nodes are rebuilt on refresh; history selection remains governed by its existing cache.

`ReadSidebarAsync` runs `for-each-ref` upstream tracking and NUL `ls-files --stage` off-thread, selecting mode-160000 stage-zero gitlinks. It reads index metadata rather than scanning files; each output is capped at 4 MiB, combined sidebar task at 20 seconds. Tracking counts use local objects and can be expensive on very large divergence; they never delay first history. Stashes use the existing bounded list reader. Git read failures retain rows and raw session Diagnostics. [Official ref tracking format](https://git-scm.com/docs/git-for-each-ref), checked 2026-10-29.

History enumeration now includes saved `refs/stash` reflog tips as explicit roots and synthetic `stash@{n}` labels; other reflogs remain excluded. Their selectors/hashes participate in snapshot fingerprints, invalidating pages after pop/drop. Reading saved tips adds one bounded local process only when `refs/stash` exists. **Current bound: 256 saved stashes**, chosen to bound process arguments for SHA-256 IDs; more produces an explicit read-limit error, never a partial list masquerading as complete history. Since 0.26.0, private index/untracked parents are folded as described above. The older stash inspector's 1,000-entry limit does not raise this history bound.

An already displayed ref selects/scrolls immediately. Otherwise `LocateHistoryAsync` runs topology-ordered `rev-list`, locates its offset and reads that 200-row page with existing fingerprint checks. It is off-thread, cancellable, bounded to 16 MiB of IDs and 30 seconds; it may fail on very large histories and does not claim constant-time seeking. Rows survive failure. A jumped page starts new graph lanes; subsequent Older pages carry that cursor. All Commits returns to the start; ordinary uninterrupted pagination is unchanged.

Submodule submission revalidates identity, current index gitlink path/hash and operation state. Paths must stay inside the worktree and contain no existing reparse components. The parent common-directory mutex is joined by the initialized child's common-directory mutex on the same worker thread; busy child/parent actions refuse instead of overlapping. External Git clients do not share these gates; Git locking remains authoritative. `submodule update --init --checkout -- <path>` with `submodule.recurse=false` targets the recorded commit, preserves normal dirty-worktree protections and may fetch required objects through the existing askpass runner. `submodule sync -- <path>` updates that URL configuration. No `--force`, `--remote`, recursion, implicit commit/stage or rollback. Partial initialization is retained and reinspected. Opening a child performs background local identity validation and reuses normal tab loading. Official [submodule update and sync](https://git-scm.com/docs/git-submodule), checked 2026-10-29. Nested management, add/remove/deinit, remote-latest updates and live submodule-auth validation remain deferred.

## Local repository initialization (0.21.0)

`RepositoryInitWindow` / `RepositoryInitViewModel` contain options only; `ShellInitialization` owns the submitted task and automatic tab selection. `GitActionViewModel` also supports an operation without a pre-existing repository context, reusing bounded output, progress, cancellation and reinspection. Menus/dialog construction do no preparation. Core `RepositoryInitialization.cs` handles validation and execution on a worker; no new dependency or settings schema.

After submission, discover Git if needed, normalize the absolute destination and inspect its nearest existing ancestor. Preserve Git ownership checks. Open an existing exact worktree root without running init. Reject nesting inside another worktree, bare repositories, metadata destinations, filesystem symlinks/junctions and malformed/inaccessible metadata. Existing linked worktree roots can open normally. These are supported-scope restrictions, not approval prompts; bare creation, nested init and linked-path creation remain deferred.

For a new repository, validate an explicit branch with `check-ref-format --branch`, then run structured `git init [--initial-branch=…] -- <destination>`. Blank omits the option. Retain configured defaults/templates; scrub inherited Git redirection and disable incidental fsmonitor/maintenance/lazy fetch as for existing commands. No implicit files, commit, staging, remote or network operation. Templates may copy configured hooks, but init does not execute them. See official [git init](https://git-scm.com/docs/git-init), [branch validation](https://git-scm.com/docs/git-check-ref-format) and [repository discovery](https://git-scm.com/docs/git-rev-parse), checked 2026-10-29.

A canonical-path named mutex excludes the same destination across Shovel profiles before a Git common directory exists. Recheck ancestors immediately before execution. This is not an atomic lock against external tools, path replacement, aliases or concurrent parent/child creation. Git retains its normal lock/ownership protections; no global configuration is modified. Preflight uses known ancestor entries, not recursive scans. Init has a two-minute process bound and 1 MiB output cap. Afterwards a fresh 20-second inspection scope can observe a usable result even after cancellation; never delete partial files, retry or claim rollback. An unexpected outside worktree is not automatically opened. OS filesystem calls, especially unavailable network shares, may outlast token cancellation.

The shell blocks competing actions/tab changes until completion and reconciliation, then uses normal history/count loading and settings persistence. Failed creation keeps the prior tab; a known usable destination becomes selected. The 20-tab bound applies before creation. Output remains in memory with credential redaction, not diagnostic logs. Destination identity before creation is path-based; after opening, normal repository identity validation applies.

## Integrated branch management and drafts (0.22.0)

`BranchManagement.cs` and its dedicated view/model/shell module reuse structured CLI execution, common-directory exclusion, cached dialogs and post-action reconciliation. Local deletion uses `branch --delete`; upstream changes use Git's local configuration commands. Identity/ref/config/linked-worktree checks cannot provide an atomic transaction against external Git clients. Original [Task 1 handoff](handoffs/task-1.md) records implementation details and race limits.

`Core/Drafts/CommitDraftStore.cs` and `CommitDraftCoordinator` persist subject/body under `%LOCALAPPDATA%/GitGui/CommitDrafts`, shared across profiles but keyed by physical worktree identity. Storage is plaintext local user text, never diagnostic output. Atomic replacement, revision checks and recovery copies preserve conflicting writers; 600 ms debounce/two-second scheduling bound, 512 KiB records and bounded cancellable I/O. Successful submission clears only that generation. Last unsaved keystrokes can be lost on a crash; Git commit and draft-clear are not one transaction. Retained old-identity/recovery files have no automatic expiry. Close all profiles before manual recovery/removal. [Task 2 handoff](handoffs/task-2.md) owns detailed recovery-file formats and limitations.

**0.27.1 storage failures:** every attempt tracks an allowlisted operation/stage. Only Windows sharing/lock errors 32/33 retry, with at most three cancellable delays of 50/100/150 ms (300 ms total backoff, excluding I/O), within the coordinator's existing five-second deadline. Retry the whole operation after releasing handles and temporary files, revalidating physical identity and expected revision; never blindly replay atomic replacement over a newer save. The writer gate retains its separate two-second wait for sharing/lock contention, without another outer retry. Other I/O failures fail promptly. Existing read handles already permit deletion/replacement and remain unchanged. Revision conflicts retain the canonical winner and use the coordinator's existing separate recovery copy. No Git retry, polling, synchronous UI work or storage migration is introduced.

App composition connects the store's typed diagnostic callback to the bounded asynchronous log. `DraftStorageRetry` / `DraftStorageFailed` add only operation, stage and nullable numeric native error to ordinary time/event/failure fields; no draft text, identity keys, paths, arguments or exception strings. Decode native codes only from Win32 exceptions or Win32-facility HRESULTs. Official error meanings checked 2026-10-29: [Microsoft system error codes 0–499](https://learn.microsoft.com/en-us/windows/win32/debug/system-error-codes--0-499-). Error 32 is a sharing violation; 33 is a lock violation, distinct from permission/disk-full failures. The reproduced publication lock explains that fixture, not retrospectively the uninstrumented 0.22 failure; [roadmap](roadmap.md#current-status) retains the evidence boundary.

The opt-in `HistoryPerformance*` harness uses isolated empty-tree diamond fixtures and samples host/owned-child resources. Headless host memory includes harness/JIT overhead; polling can miss short-lived children/peaks. It is not desktop startup or asset-repository evidence. Million-commit and five-minute idle runs remain opt-in. [Task 3 handoff](handoffs/task-3.md) documents metric semantics.

## Startup, lifetime and settings

App shows loading shell, loads settings off-thread and automatically reads selected restored tab. Schema-4 identity stamps are replacement detection, not consent. 0.7.0 ignores legacy narrower scopes and writes All Commits. Identity writes serialize with settings; failure is visible without hiding history.

Closing stops new inspections/navigation, cancels/drains startup/reads, captures plain layout on dispatcher, saves off-thread and bounds diagnostic drain. Save failure offers stay/retry or explicit exit without saving. Dispatcher/startup failure shows localized generic error, exits without saving invalid state; fatal logging best effort. Per-profile mutex excludes app writers. No tray/autostart/polling/startup fetch exists.

Options close on submission; shell-owned preparation/execution/reconciliation blocks main close/tab navigation until finished. Main close shows Operation details while busy; cancellation drains then reinspects. Common-directory mutex coordinates linked-worktree actions. This is not the future updater/external-tool idle coordinator.

Settings: `%LOCALAPPDATA%\GitGui\Foundation`, or explicit absolute `--data-directory`; separate from binaries. Stores layout/navigation, up to 20 tab paths/order/selection, legacy scope and identity stamps; no history/credentials. 64 KiB input/output, normalized values. Schema 1/2/3 → 4; previous bytes backed up on atomic replace. Same-directory temp, cancellation check, move/replace; external change since load blocks saving. Invalid/newer/unsupported/inaccessible files stay untouched. No general migration engine/recovery/export UI or automatic backup restore; older previews open newer schemas read-only. Local Changes resolves staging, then closing it returns to recovery controls. Reopening reads repository state; no intent/durable recovery command is stored or replayed. Settings schema is unchanged.

Recovery uses the same common-directory mutex and bounded runner. After submission: recheck repository identity, HEAD/branch, operation/state fingerprint and index; Continue checks `ls-files --unmerged -z`. No all-ref enumeration, remote lookup or full status scan before the write. Stage is allowed between observation and Continue; the sequence fingerprint excludes the index. Dispatch exactly the detected `merge|rebase|cherry-pick|revert --continue|--skip|--abort`; Git retains its own locks and protections. External clients remain outside Shovel's mutex; validation cannot close every race or detect an identical state being recreated.

Set `GIT_EDITOR=true` to retain the prepared message without a hidden editor; `GIT_SEQUENCE_EDITOR=false` prevents invisible todo editing. Preserve hooks/signing and existing rebase exec commands; this increment adds no interactive todo/message editor, signing broker or conflict editor. Existing closed stdin, progress/cancellation and five-minute command bound apply. Disable automatic submodule recursion/maintenance/lazy fetch as in other actions; do not change config files. Configured programs can still need an external interaction route.

Read HEAD/markers/unmerged index with a fresh 20-second token even after cancellation or failure; then the shell refreshes history/counts before reopening mutation/navigation admission. Useful rows stay visible. Later conflicts and zero-exit auto-stash conflicts are incomplete outcomes; unknown post-command state is conservatively pending. No automatic abort/drop/reset/lock deletion/retry. Git metadata is the recovery record after restart; raw output stays bounded/redacted/in memory. Full reconciliation time is separate from command time and can exceed the fast cached-control layout.

Official command semantics checked 2026-10-28: [merge continue/abort and its incomplete restoration limits](https://git-scm.com/docs/git-merge), [rebase continue/skip/abort](https://git-scm.com/docs/git-rebase), [cherry-pick sequencer](https://git-scm.com/docs/git-cherry-pick), [revert sequencer](https://git-scm.com/docs/git-revert). Abort attempts pre-sequence restoration; Skip abandons the current patch. Neither guarantees recovery of all uncommitted content.

## Local Changes and commit (0.13.0)

`Core/Git/LocalChanges.cs` reads porcelain v2 with NUL boundaries, `--untracked-files=all`, explicit rename detection and optional `--ignored=matching`. Strict UTF-8/field-boundary parsing preserves spaces/control characters and consumes rename origins as the following NUL field. Index/worktree columns become separate rows; unmerged records stay exclusively Conflicted. Parsing/sorting and row preparation run off-thread. Invalid UTF-8, 4 MiB output or 20,000-entry limits fail visibly without publishing a partial list. Existing runner: 15 s/command; whole read chain 45 s.

Status can compare file content through clean/process filters. Enumerate only matching effective filter key names with a bounded NUL config read, then override clean/process to empty and required to false for this command. Existing read arguments disable fsmonitor, optional index writes, paging, maintenance and lazy fetch. No configuration edits or external diff/textconv. `--ignore-submodules=dirty`/disabled submodule summary avoids nested content scans, showing pointer changes only. Filter normalization is deliberately not run: filter/LFS-sensitive paths may differ from ordinary status. These limits are disclosed in UI help. Config can change between commands; this is not isolation against a hostile concurrent configuration edit. Status is an observation, not an atomic snapshot of arbitrary external edits. [Official porcelain-v2 and background-status documentation](https://git-scm.com/docs/git-status), checked 2026-10-28.

`ShellChanges` now opens an owned `CommitWindow`/`CommitViewModel`, leaving the history control mounted. Construction binds available rows/draft without Git/filesystem work; Loaded yields before `ReadWorkingCopyAsync`. One selected-tab status count runs after history publication, with its own cancellation/generation and identity-before/after checks; modal opening/tab switching cancels it. No polling or inactive-tab preload. At most three populated status caches, one active diff and one action; index/status limits above remain. Full modal contexts may survive in those caches; bounded last output survives cache eviction until the tab closes (maximum 20 tabs); drafts use the durable 0.22.0 store described above.

`WorkingCopyContext` binds identity, inspected HEAD/branch/operation, status, SHA-256 index content stamp, effective config hash, filter overrides and bounded prior/merge messages. Reads and row/diff preparation run on workers. Since 0.16, mutations cancel obsolete reads without waiting for their drain; generations reject late results and close drains all chains. The common-directory named mutex is shared with branch/network actions; recheck identity, HEAD, branch, sequence, index and config before executing. This detects many external changes but is not an atomic transaction with other clients; whole-file staging intentionally uses current disk contents. No global Git config changes or stale-lock deletion.

File actions use global `--literal-pathspecs` with UTF-8 NUL pathspec files, never shell text. Stage uses `add --all` for selected paths; since 0.16 Unstage uses `reset --quiet --no-refresh <observed HEAD>` with those explicit paths, or unborn `rm --cached --ignore-unmatch -r -f`. Both affect only the index, preserving HEAD and working files. Rename origins join the path set when appropriate; ignored files are excluded. Explicit add honors clean/LFS filters. Commit uses a bounded UTF-8 message file, `--cleanup=strip`, optional `--amend`, closed stdin and no requested editor; hooks/signing remain enabled. Unresolved index blocks commit, pending resolved merge is supported, other sequences rejected. Amend confirms the actual observed tip in App. Temporary message/pathspec files are deleted in finally; no repository cleanup. [add](https://git-scm.com/docs/git-add), [path-limited reset and no-refresh](https://git-scm.com/docs/git-reset), [commit](https://git-scm.com/docs/git-commit), checked 2026-10-28.

`FileDiff.cs` selects HEAD→index (`diff --cached <hash>`), index→worktree (`diff`) or empty→untracked (`diff --no-index`). Explicit `--no-ext-diff --no-textconv --no-color`, filter overrides, no lazy fetch, pointer-only submodules. A NUL numstat read identifies binary/add/remove counts unless bounded metadata already identifies binary content (see 0.16 below). Strict UTF-8 patch parsing produces typed hunk/context/add/remove lines and old/new numbers. Combined conflict diff remains raw combined text with an explicit notice, not a conflict editor. Ignore-whitespace and whole-file context change real reads. Caps: 2 MiB patch, 20,000 lines, 16,384 characters/line; fail visibly instead of displaying partial data. Reparse paths/directories and unsupported encoding have summaries. Index digest/file size+mtime are checked again before binding; eligible hunk previews additionally hash worktree bytes as described below. [diff](https://git-scm.com/docs/git-diff), checked 2026-10-28.

One status chain and one latest-selection diff chain per dialog; selection changes cancel/drain prior diff, generations reject old results, repeated bound selection does not restart the read. WPF grids recycle rows; selected path persists for the session; drafts also persist on disk since 0.22.0. Failure retains rows but removes write readiness. Refresh/Cancel share one control; a 250 ms timer serves active commands only, with top-center duration and bounded redacted in-memory output. No bottom activity bar/ticking footer or content diagnostic logging. Message maximum 64 KiB UTF-8; UI text fields also have character bounds. Closing cancels/drains and reinspects after writes, then shell refreshes related history. Dialog opening itself never fetches. Commit and Push performs a real commit first, revalidates its new tip/config/identity, then uses existing normal Push/askpass to the configured upstream. Missing upstream disables that variant; push failure does not retry/undo a successful commit. Successful Git commit with failed tip inspection clears the draft and reports uncertainty without pushing.

Raw action output is <=1 MiB per command, combined commit/push retained output <=2 MiB; at most 20 open-tab session drafts/results. A cancelled process may already have changed Git state; reconciliation uses a fresh token, never replay/rollback. Existing browser/signing/interactive-hook limitations remain: closed terminal input, visible running/cancel/timeout, no claim to detect arbitrary helper input waits. Status scans of huge trees can still time out. No image preview, text side-by-side diff, arbitrary-line staging, ignored-file UI, discard or in-app conflict editor in this release.

## Fast file results and binary metadata (0.16.0)

File/hunk preflight reuses validated repository locations and reads HEAD/branch/operation without remotes/upstream. Commit retains full metadata validation. Successful whole-file Stage/Unstage with at most 128 paths and a conservative 16,000-character argument budget reads **only affected paths** through porcelain v2. Index digests before/after that read must match. Merge real target entries into the cached list and publish a new context; no optimistic success. Pathspec files still carry the write targets, including rename origins. Config hash validation permits reuse of the context's helper-suppression overrides. Hunk/commit, larger selections, cancellation, command failure or failed scoped reconciliation use full reconciliation.

After publishing scoped rows, release the action state, retain same-path selection across staged/unstaged and schedule a full scan after a 400 ms trailing delay. A subsequent action cancels/supersedes it without waiting for old diff/status reads; all use the existing two-process bound. Background success refreshes the context and selected diff without clearing useful content. Failure retains successful target rows/output but marks stale and removes write readiness. Unrelated rows can remain stale until this scan; external writers are independent, and observation checks cannot eliminate races. Large indexes, selected assets/filters, locks and storage can still take time. No polling/preload; [measurements](roadmap.md#fast-file-actions-and-binary-cards-2026-10-28) distinguish target-row readiness from completion of a whole-repository scan.

`BinaryMetadata.cs` shares old/new size reads between working-copy and committed diffs. Stored blobs use `cat-file -s`; only blobs below 1 KiB are read for v1 LFS pointer fields (version, SHA-256 oid, logical byte size). Recognized pointers display **asset bytes**, not pointer-file bytes. Worktree files supply length and at most an 8 KiB prefix; materialized LFS files use their actual length. A NUL prefix or recognized pointer conservatively selects a binary summary, avoiding patch/hunk hashing; other files use Git numstat. No LFS download, clean/smudge/textconv/helper or provider request. A bounded 256-object cache retains metadata only. Legacy/malformed pointers remain ordinary content; missing objects fail locally. [Official LFS pointer specification](https://github.com/git-lfs/git-lfs/blob/main/docs/spec.md), checked 2026-10-28.

Shared `BinaryComparisonView`/`BinaryComparison` displays original Old/New file cards, extension, KiB/MiB/GiB/TiB and exact bytes, LFS labels and explicit absent-side state. Empty files are not absent files. Localized accessible descriptions carry the same meaning without colors; shared semantic diff/system brushes preserve high contrast. No image decoding or external preview tool is introduced.

## Selected hunks (0.14.0)

`Core/Git/HunkPatch.cs` maps an immutable reader-produced patch to complete blocks. Diff uses explicit a/b prefixes, standard line indicators, three context lines and zero inter-hunk context. Only a single ordinary tracked modification with matching regular-file modes is eligible. Header/line-count validation excludes path/mode/add/delete/combined side effects. Available scope: UTF-8 text with ordinary text/EOL normalization; no arbitrary-line editing. Binary, rename, added/deleted/untracked, submodule/conflict and display-only whitespace/whole-file previews retain whole-file actions. Active filter, working-tree-encoding or ident attributes disable hunks, preventing suppressed read-time conversions from becoming staged content. Attribute inspection uses bounded NUL `check-attr`; no helper runs. [Diff](https://git-scm.com/docs/git-diff), [attributes](https://git-scm.com/docs/git-check-attr), checked 2026-10-28.

The existing common-directory gate owns execution. Re-read the exact diff, SHA-256 worktree bytes and effective attributes; compare with the selected preview and existing identity/HEAD/operation/index/config stamps. A temporary UTF-8 patch contains only chosen complete blocks. Run `apply --check --cached`, revalidate, then `apply --cached --whitespace=nowarn` (plus `--reverse` for Unstage); explicitly disable configured whitespace relaxation. No worktree write, whitespace fixing, reject files, three-way fallback or whole-file retry. A failed check/write retains Git output; the temporary patch is deleted in finally. Git applies the selected patch atomically or fails; cancellation can arrive after a successful index write, so the shared action flow always reinspects. [Apply documentation](https://git-scm.com/docs/git-apply), checked 2026-10-28.

Eligible text previews hash working bytes before/after reading, detecting same-size/same-mtime edits even outside displayed context. These observations still cannot exclude an external writer changing data after the last check; the Shovel mutex does not lock other clients and Git's index lock remains authoritative. Hashes are not a filesystem transaction. Whole-file/binary preview observations retain their existing limits.

The recycled diff grid maps selected rows to distinct hunk IDs with linear-time membership checks. One localized Stage/Unstage hunk button reports count/availability; accessible row text includes block number. Replacing a diff clears its selection; refresh publishes context and rows together and disables old write readiness. Hunk commands reuse progress, cancellation, retained draft/path/output and reconciliation; opening adds no Git work before display and no background polling.

## Proposed update mechanics

Use selected framework manifest, not custom protocol. U2 plus proposed channel/OS/arch/minimum version-schema/size/hash/signer/verified notes. Supported schemas/HTTPS only; reject redirects/login pages/downgrades/replay below installed or trusted version. Verify before executing; render notes as plain/inactive text.

Check after shell startup with timeout/backoff, no overlapping periodic checks. Bounded staging, full reverify after resume; cancel discards/quarantines partials. No auto-install on download/exit/startup.

Explicit Restart and update: cross-instance shutdown gate stops new work, rechecks all repos/commands/prompts/tools/sequences, persists session, revalidates package and hands off only if idle. Unknown tool completion needs verification/acknowledgment. Installer cannot force-kill/race new launch; save failure cancels shutdown. Unresolved startup recovery blocks install.

### Signing and bad-release recovery

Updater signatures (e.g. Ed25519) authenticate feed/package via bundled public key; Authenticode/MSIX establishes Windows publisher trust; HTTPS is transport. Keep private keys out of repo/app/artifacts/logs, with restricted CI/hardware storage and backup/rotation/compromise procedure; providers/budget/IT trust open.

Retain known-good artifacts/schema backups, pilot first. Withdraw bad manifest, keep clients usable, issue higher-version corrective release compatible with affected schema. Separate reachable signed repair installer for nonstarting app; no routine uninstall. Explicit downgrade/data restoration only; no unverified automatic rollback/power-loss atomicity.
