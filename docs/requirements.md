# Requirements and acceptance

Updated 2026-10-31. Confirmed unless marked proposed. IDs remain stable. [Product](product.md) owns UX; [architecture](architecture.md) mechanisms; [roadmap](roadmap.md) evidence. Deferred scope may advance when requested; phase labels do not veto independent feature work.

## Git functionality and compatibility

**Clone/remotes acceptance (0.33.0, G1/G2/G5/G7/G13):** options opening and dismissal perform no preparation. Submission executes native Git with progress, cancellation, retained errors and existing authentication; successful clones automatically open history, including empty/detached repositories. Keep filters/hooks and partial results; refuse nonempty destinations without removing user files. Remote URL changes preserve working/index files and local branches, remove requires target-specific confirmation, and no edit/removal performs network discovery. Stale configuration, locks and partially completed URL updates must report actual results and reconcile. Multi-URL/inherited configuration is not silently flattened. Disposable Git and headless renders do not establish live-server authentication, large-clone latency or installed desktop behavior.

**QOL acceptance (0.31.0):** file/commit switches keep the previous labelled comparison until a generation-matched result arrives; empty success clears it and failure retains it. Old hunks cannot authorize actions. Unchanged refreshes retain selected row objects, and history/stash selection opens Commit changes. Whole-file conflict controls live inside the existing Commit pane, start with both sources selected and apply/stage only on submission. Persist window/pane geometry across clean sessions with bounded schema migration. The central activity panel filters real user/background operations without reads on opening, caps entries/output, redacts URL credentials and writes no activity log to disk. Preserve normal input, theme/high-contrast roles and responsive cancellation; headless checks do not certify physical focus or DPI behavior.

**Confirmed direction (2026-10-30):** personal Fork replacement precedes team rollout. Direct Pull/history actions and Fetch/Push are delivered; 0.30.0 adds named-side conflict resolution and text editing. Acceptance covers actual staged results, merge/rebase/stash provenance, deletion/binary/LFS choices, stale files/index/attributes, retained edits on failed/cancelled execution and external-tool failure. Merge/rebase banners must open Local Changes or abort the detected operation. Startup previews must be bounded, visibly stale and unable to authorize mutations. Stash menus perform real Apply/Pop/Drop without opening-time work; tab order persists and disabled chrome remains themed. Discard evidence must separate validation, native command and reconciliation, single/batch assets, UI responsiveness and exact-byte correctness; do not infer a fix for an unreproduced 30-second event. [Product](product.md#conflict-resolution-and-faster-reopening-0300) owns UX and limits; LFS locking remains low priority.

Measure validation, native command and refresh separately; UI automation overhead is not command time.

**History actions (0.29.0):** menu opening must perform zero Git/filesystem preparation; target the clicked full SHA, reject stale tab/page/ref/config snapshots and preserve selection/virtualization/keyboard access. Revert must create a new commit, require an explicit merge mainline and expose conflicted recovery. Failed/cancelled actions retain output and reinspection; no automatic rollback. Default Push resolves a supported single-branch destination without substituting Pull upstream or publishing multiple refs.

**Stashes (0.18.0):** create with optional untracked files; inspect saved tracked/index/untracked content; apply/pop with explicit staged-state restoration; confirmed exact-target drop. Submodule update targets the indexed commit without force or recursion; ordinary file/ownership/auth protections remain. Deferred management actions are omitted, not placeholders.

## Execution and data handling

**Workspace cleanup (0.27.0):** sidebar has vertical scrolling only, trimmed labels and no fixed maximum width beyond the available window. Remove its duplicate repository title/Local Changes link and the main footer; retain toolbar Commit and Help version. History page navigation/range/status moves to View, keyboard and page-edge scrolling; limits remain visible in Diagnostics and failed reads retain an error route. Enlarge caption icons and shorten tooltips without losing accessible meaning. History reads/refreshes report measured durations with entrance/completion fades, accurate cancellation/failure and action-timer priority. Remote creation opens without I/O, saves local config with no fetch, then supports explicit Fetch and upstream set/unset; duplicate/stale/cancelled submission cannot silently overwrite configuration. Preserve real stash-only commits; distinguish the stash marker and its single base connection even if internal objects are independently reachable.

**History/caption layout (0.26.0):** one visible row for ordinary saved stashes, with original details/inspector data retained and independently reachable objects protected. Folding must preserve 200-row visible pagination, ref navigation and stale-result checks. Branch columns/colors remain stable until convergence; rounded edges must connect across rows/pages without missing parents. Main menus share the draggable caption; caption commands preserve existing shutdown and normal window management. Native desktop behavior needs explicit verification, separate from offscreen layout checks.

The established work environment is trusted. **Do not add extra safety measures, repository-trust modals, first-use approval layers or repeated consent for routine Git actions.** Use normal operation controls; confirm actual destructive scope and honor required authentication/host verification. This replaces older routine trust-gate requirements.

## Verification and acceptance

**Direct Pull (0.28.0):** prove the main command actually rebases divergent disposable history without showing options, publishes progress and retained output, blocks duplicate submission and refreshes real rows. The arrow must open the existing editable modal with zero preparation calls and still execute chosen Merge/auto-stash settings. Missing upstream disables only the direct action; changed/custom server mappings must fail before fetch. Cancellation and dirty-worktree failure retain usable history/files. Review both controls in offscreen normal/minimum Dark/Light layouts; no desktop-speed claim from these checks.

**Confirmed routine policy (2026-10-29, 0.22.1):** default and preview verification run at most 30 explicit smoke checks (currently 26). Target <120 seconds; independent watchdogs enforce 180 seconds overall and 30 seconds/check. Stop at the first failure and print check/runtime. Count setup time toward the suite limit. Existing full regressions and detailed feature suites are optional, chosen for relevant changes/failures; the matrices below describe available acceptance coverage, not mandatory work for every delivery. Never compress hundreds of cases into 30 labels. Build success, smoke success and full regression success must be reported separately.

0.22 integration: disposable checks cover branch merged/current/linked-worktree protections, tracking, stale target/config and cancelled/partial outcomes; isolated draft tests cover atomic saves, revisions, recovery copies, replaced identity, linked worktrees, failed/successful commits and delayed restoration. Small performance-harness checks verify deterministic topology, cancellation, owned cleanup and sampler behavior. Full million-scale/idle measurements and physical crash/ACL/disk-full certification are separate from these checks.

**Draft I/O (0.27.1):** a temporary publication lock must recover without clearing editor text; cancellation and exhausted retries preserve the last durable record. Retry only identified sharing/lock failures and recheck identity/revision on every attempt. A newer competing save remains canonical while this window's conflicting text is saved separately when possible. Verify bounded attempts, prompt non-sharing failure, unchanged modal-opening behavior and diagnostics containing only allowlisted stage/operation/numeric OS error. Focused isolated-file checks are optional; they do not certify power-loss, real ACL/disk-full handling or explain an older failure without its error metadata.

Build/headless evidence is distinct from desktop/live-auth/installed verification. Use meaningful parser/process tests and disposable real-Git integration fixtures with isolated config/test hooks; never destructive tests on working repositories. Live accounts/desktop launches require task authorization. Record date, OS/build/architecture/Git/runtime/fixture/results/limits. **A feature is complete only when its real action works within stated scope.** Mock/layout checks cannot replace Git semantics.

Real signed N → N+1, agreed Windows 10/11 builds, standard user, both channels, disposable profiles/repos and controlled endpoint.

| Case | Required result |
| --- | --- |
| Success | Launch-time automatic restart or explicit restart installs verified N+1 in place, correct version/status, no routine uninstall/elevation where supported. |
| Postpone | N remains usable after cancelled/blocked work; no idle/exit install. Each new launch checks again and may automatically update. |
| Hosting | Offline/DNS/timeout/5xx/proxy/401/403 leaves startup/Git usable; manual retry, no tight loop. |
| Invalid content | Reject altered feed/package, wrong signer/architecture/channel, truncation/login HTML before execution. |
| Interrupted download | Cancel/loss/crash leaves N usable; resumed/restarted bytes fully reverified. |
| Data | Preserve settings/tabs/drafts/recovery; migration backup; invalid/newer schema not overwritten. |
| Busy/race | Git/hook/auth/tool/conflict blocks, including work starting before shutdown or in another instance. |
| Resource/install failure | Low disk/locked files/permissions/installer/app crash preserves data; documented repair, no untested rollback claim. |
| Bad release/channel | Test pilot isolated from stable; withdraw manifest, higher corrective release and offline repair tested. |
| Publication | Package verifies before manifest; signature mismatch rejects, later retry recovers; installed version usable. |
